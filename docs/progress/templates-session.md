# Learning session handoff template

Create a uniquely named session note. Record facts rather than presumed understanding.

- Date/time and human-authorized scope.
- Concepts explained, examples used and questions still open.
- Last user-confirmed action; distinguish assistant demonstrations from user work.
- Files actually written and commands actually run, including who performed them.
- Verification results and evidence; explicitly identify unrun or failed checks.
- Accepted decisions and relevant engineering/feature IDs.
- Incomplete work and concrete blockers, if any.
- Next single lesson/action, with its purpose and prerequisites.
- Retained services/resources and cleanup, without secret values.

Update state.json and CURRENT.md manually. Implementation and parity verification are separate statuses. No tooling is currently installed to generate these documents.
